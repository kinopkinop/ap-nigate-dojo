# AP理解道場 問題設計ガイド

AP理解道場は、用語を覚える場所ではなく、既に知っている知識を短い状況へ適用する場所とする。用語の初回学習は「AP苦手だけ道場」が担当し、両者の役割を重複させない。

## 必須の問題構造

各メイン問題と確認問題は、次の要素を持つ。

1. `theme`: 扱う知識領域
2. `skill`: その問題で確認する判断能力。同じthemeでも異なる判断を求める場合に分ける
3. `situation`: 実務・システム・プロジェクトなどの短い具体例
4. `conditions`: 判断に必要な条件
5. `question`: 状況に対して最も適切な答えを選ばせる問い
6. `choices`: 同じ領域で混同しやすい選択肢4個
7. `explanation`: なぜ正解なのか
8. `clues`: 問題文のどこを判断材料にしたか
9. `comparison`: 他の選択肢がなぜ不十分か
10. `keyPoint`: 次の類題で使える短い判断基準

学習の流れは「具体的な状況 → 条件を読み取る → 知識を適用する → 選択する」とする。1問は10秒〜2分程度で判断できる長さに収める。

## 作成しない問題

- 「○○とは？」だけの定義問題
- 定義文と同じ表現を選ぶだけの問題
- 略語の正式名称だけを問う問題
- 数字だけ、選択肢の順番だけを変えた同一問題
- 直前の問題をほぼ言い換えただけの確認問題
- 正解と無関係な分野の、明らかに誤りと分かるダミー選択肢

## 重複チェック

問題追加前に、既存データの `theme` と `skill` を確認する。

- themeもskillもほぼ同じなら追加しない
- themeが同じでも、別の状況で異なる判断を求めるskillなら追加できる
- 確認問題は、比較・別の具体例・条件変更・逆向きの判断など、メイン問題とは異なる思考を要求する
- 数値だけを変えることは「異なるskill」とみなさない

## 確認問題の追加制約

確認問題は、直前の正解用語を覚えているだけでは解けない形にする。

- メイン問題の正解用語は、原則として確認問題の状況・条件・質問・選択肢に出さない
- メイン問題と同じ選択肢セットを使わない
- 正解用語を別の文章で再選択させず、仕組み・原因・判断根拠・見るべき情報・不足する理由・起きる結果・条件から導ける関係を問う
- メイン問題や解説に出した特徴的な一文を、そのまま正解選択肢として再利用しない
- メインが「状況から用語・状態を選ぶ」なら、確認問題は「結果から原因」「技術を使う理由」「状態から条件」「防止要件から方式」など思考方向を変える
- 正解用語は、回答後の解説で知識と結び付けるために使用してよい
- 問題文から正解用語を完全に除くと不自然になる例外では、短期記憶だけで解けない別のskillであることを確認する

## 分野別の判断例

- セキュリティ: 攻撃内容や要件から対策を選ぶ
- データベース: トランザクションや表の変化から現象・設計を判断する
- ネットワーク: 通信要件や構成からプロトコル・機器・設定を選ぶ
- マネジメント: プロジェクトの状況や数値から状態・対応を判断する
- ストラテジ: 企業や市場の状況から分析・施策を選ぶ
- テクノロジ: 処理条件・性能・アルゴリズムから方式を選ぶ

## 実装上の注意

- 問題は `app/understandingQuestions.ts` で管理する
- `id` は学習履歴のキーなので、既存問題の意味を維持する修正では変更しない
- `followUp` は任意だが、設定する場合も同じ設計基準を満たす
- 選択肢の表示順はUI側でランダム化するため、データ上の `correctIndex` は元の配列位置を指す
- AP苦手だけ道場の用語データ・出題ロジック・localStorageには影響を与えない
